# Каркас личного харнеса поверх KISA Stack — дизайн

Дата: 2026-09-20. Статус: на ревью у владельца.
Подпроект 1 из 4. Остальные три (MCP-синк, память, защита) получают свои спеки.

## Цель

Превратить форк `kisa-stack` в личный дистрибутив харнеса: одна команда
разворачивает скиллы, правила, хуки и подключение MCP deploychan на любой
машине (Windows и Linux) в рантаймы Claude Code, Codex CLI и Hermes — не ломая
то, что там уже настроено.

Основание — маршрут `agent-harness` из MCP deploychan (хуки → правила как
стабильный префикс → память → самоаудит) и дисциплина базового скилла
`tailored-install`: детект окружения, никакой слепой перезаписи, отчет о том,
что изменилось.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Что такое «свой харнес» | Репозиторий-дистрибутив, а не настройка одной машины и не отдельная программа-агент |
| Рантаймы и ОС | Claude Code + Codex + Hermes, Windows + Linux |
| Отношение к апстриму | Форк с подтягиванием обновлений; свое — отдельным слоем |
| Роль MCP deploychan | И источник сборки (подпроект 2), и рантайм-подключение (этот подпроект) |
| Память | Вики + FTS5 (подпроект 3) |
| Правила | Методология Кисы из шаблонов апстрима + личный блок поверх |
| Реализация каркаса | Обертка над `install.sh` апстрима, bash |
| Хуки и вики-секция | Включены сразу, `WIKI_ENABLED=1` по умолчанию |

## Инварианты

1. **Все свое живет в `overlay/`.** Ни один файл апстрима не правится, включая
   `.gitignore` и `README.md`. `git pull upstream` не дает конфликтов.
2. **`install.sh` апстрима используется буквально**, без правок и без копии
   его логики.
3. **Слияние, а не перезапись.** В чужих файлах харнес владеет только своим
   управляемым блоком или своими ключами. Все остальное сохраняется
   байт-в-байт.
4. **Идемпотентность.** Повторный `apply` без изменений во входных данных не
   меняет ни одного файла и не создает ни одного бэкапа.
5. **`plan` не пишет ни байта** за пределами `overlay/.build/`.
6. **Не угадывать.** Путь или формат не подтвержден — харнес печатает
   инструкцию для человека, а не пишет наугад.

## Структура

```
kisa-stack/
├── skills/  global-config/  install.sh  plugins.md  README.md   ← апстрим, read-only
└── overlay/
    ├── harness.sh              единственная реализация (bash)
    ├── harness.ps1             лаунчер: находит Git Bash и вызывает harness.sh
    ├── lib/                    части harness.sh по одной ответственности
    │   ├── detect.sh           окружение, пререквизиты, какие рантаймы есть
    │   ├── stage.sh            стейджинг скиллов и вызов install.sh
    │   ├── render.sh           рендеринг правил из шаблонов апстрима
    │   ├── block.sh            вставка/замена управляемого блока в файле
    │   ├── settings.sh         слияние settings.json через jq
    │   ├── mcp.sh              подключение deploychan
    │   └── backup.sh           бэкапы и перенос backup-папок install.sh
    ├── profile.example.env     в git
    ├── profile.env             вне git (зависит от машины)
    ├── rules/claude.md         личный блок для CLAUDE.md
    ├── rules/agents.md         личный блок для AGENTS.md
    ├── skills/                 личные скиллы; сюда же пишет MCP-синк (подпроект 2)
    ├── tests/run.sh
    ├── docs/specs/
    ├── .gitignore              вложенный: profile.env, .build/
    └── README.md
```

`harness.ps1` не содержит логики установки. Он ищет
`%ProgramFiles%\Git\bin\bash.exe` (затем `%LocalAppData%\Programs\Git\bin\bash.exe`)
и передает ему `harness.sh` с аргументами. `bash` из PATH не используется: на
Windows первым находится `C:\Windows\System32\bash.exe` — заглушка WSL.

## Команды

```
overlay/harness.sh plan     # по умолчанию: показать, что изменится
overlay/harness.sh apply    # бэкап затронутых файлов, затем применить
```

Оба режима проходят один и тот же путь: каждый шаг готовит результат в
`overlay/.build/render/`, сравнивает с текущим состоянием и выдает `diff -u`. `plan` на
этом останавливается, `apply` записывает. Расхождение между тем, что показал
`plan`, и тем, что сделал `apply`, невозможно по построению.

## Профиль

`overlay/profile.env` — sourceable `KEY=value`. Отсутствует — `harness.sh`
останавливается и предлагает скопировать `profile.example.env`.

| Ключ | Дефолт | Смысл |
|---|---|---|
| `RUNTIMES` | `claude codex hermes` | Куда ставить. Рантайм без домашнего каталога пропускается с сообщением |
| `WIKI_ENABLED` | `1` | Вики-секция в правилах и хуки-якоря |
| `VAULT_ROOT` | — (обязателен при `WIKI_ENABLED=1`) | Родитель папки `LLM Wiki`. Подставляется вместо `<ПУТЬ_К_VAULT>` |
| `AUTO_MEMORY_OFF` | `0` | `1` — записать `autoMemoryEnabled: false` и оставить подсекцию «Память» |
| `MCP_OBSIDIAN` | `0` | `0` — вырезать абзац про `mcp-obsidian` |
| `DATAWEAVE_ENABLED` | `0` | `0` — вырезать упоминания ObsidianDataWeave |
| `DATAWEAVE_REPO` | — (обязателен при `DATAWEAVE_ENABLED=1`) | Вместо `<ПУТЬ_К_КЛОНУ>` |
| `RTK_ENABLED` | `0` | `0` — вырезать пункт про `rtk` wrappers из AGENTS.md |

Пути в профиле пишутся с прямыми слэшами (`C:/Users/...`) — так их одинаково
понимают Git Bash и Linux.

Каталог вики вычисляется как `WIKI_DIR="$VAULT_ROOT/LLM Wiki"`. Семантика
повторяет апстрим: в шаблонах правил стоит `<ПУТЬ_К_VAULT>/LLM Wiki/`, а хук
`wiki-anchor.sh` ждет в `WIKI_VAULT` уже полный путь с `LLM Wiki`.

### Почему `AUTO_MEMORY_OFF=0` при включенной вики

Подсекция «Память» шаблона утверждает, что авто-память Claude Code отключена и
единственный контур записи — пайплайн вики. Пайплайна записи до подпроекта 3
нет. Выключить авто-память сейчас значит оставить агента без канала записи
вообще. Поэтому в каркасе авто-память не трогается, а подсекция «Память»
вырезается, чтобы правила не противоречили настройкам. Подпроект 3 переключит
флаг в `1`.

## Пререквизиты

Проверяются до любых действий, включая `plan`:

- `bash` ≥ 4, `diff`, `sed`, `awk`, `find`, `mktemp` — на Linux есть, на
  Windows приходят с Git for Windows.
- `jq` — обязателен. Нужен для слияния `settings.json` и самим хукам апстрима:
  без него они молча деградируют (не различают `source=compact`, счетчик
  напоминаний общий на все сессии).

Нет пререквизита — остановка с командой установки
(`winget install jqlang.jq` / `sudo apt install jq` / `sudo pacman -S jq`).
Харнес сам ничего не доустанавливает.

## Шаги установки

Адаптер рантайма работает, только если рантайм обнаружен: существует
`~/.claude`, `${CODEX_HOME:-~/.codex}`, `${HERMES_HOME:-~/.hermes}`.

| | Claude Code | Codex | Hermes |
|---|---|---|---|
| Скиллы | `install.sh --claude` | `install.sh --codex` | `install.sh --hermes` |
| Правила | блок в `~/.claude/CLAUDE.md` | блок в `~/.codex/AGENTS.md` | нет |
| Хуки | `~/.claude/hooks/` + `settings.json` | нет | нет |
| deploychan | `claude mcp add`, если CLI есть | блок в `config.toml` | инструкция |

Пустые клетки — паритет с апстримом: он не поставляет ни правил для Hermes, ни
хуков для Codex и Hermes. Их добавление — не задача каркаса.

### 1. Скиллы: стейджинг вокруг `install.sh`

`install.sh` вычисляет корень репо от собственного расположения и ставит все
из соседней папки `skills/`. Этим и пользуемся:

1. Очистить `overlay/.build/`.
2. Для каждого целевого рантайма собрать список скиллов: все из `skills/`
   апстрима, затем все из `overlay/skills/`. Одноименный скилл из `overlay/`
   замещает апстримный.
3. Сравнить каждый скилл с установленным (`diff -rq`). В стейджинг
   `overlay/.build/<runtime>/skills/` попадают только отсутствующие и
   отличающиеся.
4. Скопировать `install.sh` в `overlay/.build/<runtime>/` и запустить оттуда:
   `install.sh all --<runtime>`. Пустой стейджинг — шаг пропускается.
5. `install.sh` оставляет прежнюю версию скилла рядом, как
   `<name>.backup-<timestamp>`, прямо в каталоге скиллов рантайма. Внутри нее
   лежит `SKILL.md` с тем же `name`, и рантайм может подхватить дубль. После
   установки такие папки переносятся в
   `~/.kisa-harness/backups/<timestamp>/skills/<runtime>/`.

В режиме `plan` шаги 4–5 не выполняются; печатается список скиллов со
статусом `new` / `changed` / `same`.

### 2. Правила: рендеринг и управляемый блок

Вход — `global-config/CLAUDE.md` и `global-config/AGENTS.md` апстрима. Порядок:

1. Удалить все HTML-комментарии `<!-- ... -->`. Это указания человеку,
   ставящему шаблон руками, агенту они не нужны.
2. Вырезать выключенные секции по якорям (таблица ниже).
3. Подставить `<ПУТЬ_К_VAULT>` → `$VAULT_ROOT`, `<ПУТЬ_К_КЛОНУ>` →
   `$DATAWEAVE_REPO`.
4. Убрать повисшие в конце `---` и пустые строки.
5. Дописать `overlay/rules/claude.md` (или `agents.md`), если файл непустой.
6. Обернуть в маркеры и вставить в целевой файл.

Маркеры: `<!-- kisa-harness:begin -->` и `<!-- kisa-harness:end -->`. Блок есть
— заменяется его содержимое. Блока нет — он дописывается в конец файла. Файла
нет — создается. Один маркер без пары — остановка с ошибкой. Содержимое вне
маркеров не меняется.

| Флаг = 0 | CLAUDE.md | AGENTS.md |
|---|---|---|
| `WIKI_ENABLED` | от `# LLM Wiki` до конца файла | от `# Память и LLM Wiki` до строки перед `# Skills` |
| `AUTO_MEMORY_OFF` | от `## Память` до строки перед `## ObsidianDataWeave` | — |
| `MCP_OBSIDIAN` | строка, начинающаяся с `**Проверка структуры vault` | — |
| `DATAWEAVE_ENABLED` | от `## ObsidianDataWeave` до конца файла | пункт `- Предпочитай пайплайн ObsidianDataWeave:` и его вложенные строки |
| `RTK_ENABLED` | — | пункт `- Для шумных команд предпочитай` и его строки-продолжения |

Якоря — заголовки и начала пунктов, потому что комментарии-пометки в шаблонах
свободной формы и машинно не разбираются. Это хрупко к правкам апстрима,
поэтому рендерер **падает громко**:

- ожидаемый якорь не найден — ошибка с именем якоря и файла;
- в результате остался плейсхолдер вида `<[А-ЯA-Z_]+>` — ошибка с номером
  строки. Иллюстративные `<проект-2>` в нижнем регистре под шаблон не попадают
  и остаются как есть.

Остановленная установка лучше, чем молча испорченные правила.

### 3. Хуки (только Claude Code, только при `WIKI_ENABLED=1`)

Проверки до записи:

- `WIKI_DIR` не существует — остановка: создать папку или выставить
  `WIKI_ENABLED=0`. Скелет вики харнес не создает, это подпроект 3.
- Нет `claude-code/pages/overview.md` или `components.md` — предупреждение в
  выводе `plan`, не ошибка. Хук сошлется на них, агент не найдет и сообщит.

Действия:

1. Скопировать `global-config/hooks/wiki-anchor.sh` и `wiki-reminder.sh` в
   `~/.claude/hooks/` **без правок**, выставить исполняемый бит.
2. Слить в `~/.claude/settings.json` через `jq`:
   - `env.WIKI_VAULT = "$WIKI_DIR"` — хук уже читает эту переменную, поэтому
     редактировать скрипт не нужно;
   - записи `SessionStart` и `UserPromptSubmit` из
     `settings.hooks.example.json`, с дедупликацией по полю `command`. Чужие
     хуки на тех же событиях сохраняются;
   - `autoMemoryEnabled: false` — только при `AUTO_MEMORY_OFF=1`.
3. Невалидный JSON в существующем `settings.json` — остановка, файл не
   трогается.

### 4. Подключение deploychan

Endpoint: `https://mcp.deploychan.webcam/mcp`, Streamable HTTP, без авторизации.

- **Claude Code.** Есть `claude` в PATH: проверить `claude mcp get deploychan`;
  нет записи — `claude mcp add --scope user --transport http deploychan <url>`.
  Нет CLI — напечатать эту команду как инструкцию. `~/.claude.json` руками не
  правится: это файл состояния приложения.
- **Codex.** Дописать в `config.toml` блок между `# >>> kisa-harness >>>` и
  `# <<< kisa-harness <<<` с секцией `[mcp_servers.deploychan]`. Если такая
  секция уже есть вне блока — не трогать, сообщить.
- **Hermes.** Путь к MCP-конфигу в материалах MCP не назван (сказано только
  «`mcp.json`»). Не угадываем: печатается JSON-фрагмент и инструкция.

## Ошибки и бэкапы

- `set -euo pipefail`. Первый сбой останавливает установку. Сообщение
  называет шаг, файл и что сделать человеку.
- Порядок шагов: пререквизиты → профиль → рендеринг всех файлов в
  `overlay/.build/render/` → показ диффов → (только `apply`) бэкап → запись. Ошибки рендеринга
  и валидации случаются до первой записи.
- Перед записью каждый существующий файл копируется в
  `~/.kisa-harness/backups/<timestamp>/` с зеркалом пути от `$HOME`. Файл не
  меняется — бэкапа нет.
- Команды `restore` нет. Бэкапы — обычные файлы; откат описан в
  `overlay/README.md`.

## Тесты

`overlay/tests/run.sh` — чистый bash, без фреймворка. Каждый кейс получает
свежие `HOME`, `CODEX_HOME`, `HERMES_HOME` из `mktemp -d`, поэтому Hermes-ветка
проверяется без установленного Hermes. Запускается на Linux и в Git Bash.

1. Чистая установка: скиллы на месте во всех трех рантаймах, блоки правил
   созданы, хуки и `settings.json` созданы.
2. Повторный `apply`: ни один файл не изменился, новых бэкапов нет.
3. `CLAUDE.md` с чужим содержимым: оно сохранено байт-в-байт, блок добавлен.
4. `settings.json` с чужими хуками на `SessionStart`: они сохранены, наши
   добавлены один раз.
5. `WIKI_ENABLED=0`: нет хуков, нет `env.WIKI_VAULT`, нет вики-секции.
6. Рендерер падает на шаблоне без ожидаемого якоря.
7. Рендерер падает на недозамененном `<ПУТЬ_К_VAULT>`.
8. Скилл из `overlay/skills/` замещает одноименный апстримный.
9. `plan` не меняет ничего вне `overlay/.build/`.
10. После обновления скилла в каталоге скиллов рантайма нет папок `*.backup-*`.
11. Непарный маркер в целевом файле — остановка без записи.
12. Рантайм без домашнего каталога пропущен, остальные установлены.

## Риски и спайки

1. **Исполнение хуков на нативном Windows — не проверено.** Неизвестно, через
   какой шелл Claude Code запускает команду вида
   `$HOME/.claude/hooks/wiki-anchor.sh`. Первый шаг плана реализации — спайк:
   поставить тривиальный хук и посмотреть. От результата зависит только строка
   `command` в `settings.json` (как есть либо с явным путем к Git Bash),
   архитектура не меняется.
2. **Якоря рендеринга ломаются при правках апстрима.** Смягчение — громкое
   падение и тесты 6–7. Принятый риск выбранного подхода.
3. **URL апстрима не подтвержден.** `origin` — `antonovkrez/kisa-stack`.
   Вероятный апстрим — `howdeploy/kisa-stack`; уточнить у владельца перед
   `git remote add upstream`.
4. **Слияние TOML — текстовое.** Bash не разбирает TOML; наличие секции
   проверяется по строке `[mcp_servers.deploychan]`.
5. **Подкоманды `claude mcp` не проверены на этой машине** — CLI нет в PATH.
   Точные имена (`get`, `add`, флаг `--scope`) сверить с `claude mcp --help`
   при реализации.

## Вне объема

- MCP-синк, скелет вики и FTS5, guard/zaebal/RTK — подпроекты 2–4.
- Команда `restore`, автоустановка `jq`, правка `~/.claude.json`.
- Хуки для Codex и Hermes, правила для Hermes.
- Создание содержимого вики.

Подпроекты 2 и 3 не лягут на bash (HTTP-клиент MCP, SQLite FTS5) и будут на
Python stdlib. Каркасу это не мешает: их результат — файлы в `overlay/skills/`
и новые ключи профиля.
