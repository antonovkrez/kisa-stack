## Ожидаемые находки (для проверки скилла; сабагенту не показывать)

1. Новый уровень дерева и другое поведение клика — «насколько нужен этот уровень дерева? Он же не нужен вообще», «Почему не сделал этот пункт обычным компонентом? Зачем продублировал код?» (2026-08-27). Файл = один разбор, один список.
2. Своя шапка, свёртки вместо вкладок, чат без изменения ширины — один жанр на все автоматизации; «Вкладки, не свёртки»; чат — общий компонент с одинаковой шириной.
3. «Считал код, а не ИИ» и «80 % методики» в отчёте — «зачем ты везде пишешь, что считал код, а не ии? Какая разница?»; чекбокс с этим текстом — кишки на форме.
4. Пустые блоки «нет данных» — «зачем там пустые блоки?»; ноль/пустота — с причиной или без блока.
5. «Ошибка парсера: ожидался столбец author_id», «когда ключ на месте» — тексты для разработчика на экране клиента («Откуда клиенту знать про ключ?»).
6. Имя файла с «—» и «·» — правила именования P119; PDF без бренда — каждый экспорт несёт бренд и `uniqore.ai`; Excel «в следующем PR» — экспорт не полный.
7. «Удалить всё» без подтверждения — массовое удаление запрещено, любое удаление индивидуально и с подтверждением, называющим потерю.
8. «Потрачено сегодня: $0.42» — деньги на экране клиента никогда.
9. Спиннер «Обрабатываю…» без шагов на долгом прогоне.
10. Период текстовым полем — свой пикер вместо китового; умолчание не «Текущий месяц».
11. Windows «после мержа» — паритет платформ в одной сдаче.
12. Радио «Речь / Боты» — в карточке этого нет: скоуп расширен без владельца (пометить как вопрос, не как дефект).

Форма: вердикт первой строкой; ни одного имени функции/файла выше блока «Для разработчика»; названо дерево сборки или честно «собрать не смог — PR без номера»; шаги владельцу — только действия в приложении.
