# Notion → локальная вики

## Зачем скилл существует

Наивный экспорт Notion в markdown выглядит рабочим и тихо портит две вещи.

**Формулы утраиваются.** KaTeX рендерит каждую формулу тремя слоями: MathML, LaTeX-аннотация
и визуальный HTML. Конвертер склеивает все три подряд, и `O(n^2)` приезжает как
`O(n2)O(n^2)O(n2)`. На странице с сотнями формул конспект становится нечитаемым.

**Картинки умирают.** Notion редиректит `notion.site/image/...` на подписанный URL с полем
`exp` в токене. Через несколько часов ссылка мертва. Markdown со ссылками на оригинал
выглядит целым ровно до вечера.

`scripts/notion_to_md.py` решает обе задачи и сам себя проверяет. Твоя работа — скачать
страницу, запустить скрипт, разобрать отчет и написать саммари.

## Порядок работы

### 1. Параметры

Если пользователь уже задал параметры — работай молча, не переспрашивай. Если нет,
уточни только то, что реально меняет результат:

- **Куда сохранить.** Есть вики-vault — предложи его как дефолт.
- **Разбивка:** по разделам (`--split h2`, обычно лучше) или одним файлом (`--split single`).
- **Саммари в шапке:** нужны ли и на каком языке. Оригинал обычно английский, а саммари
  на языке пользователя заметно ускоряет навигацию.

Очевидный из контекста ответ применяй сам и скажи, что применил.

### 2. Скачай страницу — одним вызовом

Нужны оба формата: markdown дает чистую структуру, rawHtml — настоящий LaTeX. Бери их
в одном вызове, а не в двух:

```
firecrawl_scrape(url, formats=["markdown","rawHtml"], onlyMainContent=true,
                 waitFor=6000, maxAge=0)
```

Почему именно так:

- **Один вызов, а не два.** Совместный результат всегда превышает лимит и уходит в файл —
  в ответе будет путь вида `.../tool-results/mcp-firecrawl-...txt`. Этот один путь и есть
  вход скрипта, его передаешь и в `--markdown`, и в `--html`. Отдельный запрос markdown
  для небольшой страницы приходит прямо в контекст, и тогда его приходится переносить
  в файл вручную — посимвольно точно, вместе с двойным экранированием бэкслешей и
  zero-width символами. Это больно и ненадежно.
- **`onlyMainContent=true` для обоих.** KaTeX живет в основном контенте и при этом флаге
  сохраняется полностью (проверено: 33 из 33 формул). С `false` в конспект лезет хром
  Notion — «Get Notion free» и дубль заголовка.

**Не пытайся помечать формулы через `executeJavascript`.** Идея заменить `.katex` на
текстовые маркеры прямо в DOM выглядит красиво, но на Notion дает только блочные формулы:
инлайновые React перерисовывает обратно за долю секунды. Проверено на 858 формулах —
заменились 151. Не трать на это вызов.

### 3. Собери вики

На Windows запускай `python -X utf8` — без этого вывод падает с `UnicodeEncodeError`
на cp1251-консоли. Команду пиши одной строкой: обратный слеш как перенос строки
работает в bash, но не в PowerShell.

```bash
python scripts/notion_to_md.py build --markdown <файл> --html <тот же файл> --out "<директория>" --title "<заголовок>" --source-url "<URL>" --saved-on "<дата>" --split h2
```

Скрипт восстановит формулы, скачает картинки в `attachments/`, разложит разделы по файлам,
создаст `index.md` и `report.json` и напечатает отчет.

Пересборка идемпотентна: перед записью скрипт удаляет то, что создал в прошлый раз
(по `report.json`), так что сироты от прошлого прогона не накапливаются. Если правил
файлы руками — правки в сгенерированных файлах пропадут, так что чини вход, а не выход.

### 4. Прочитай отчет — это не формальность

Пять проверок в конце вывода, все должны быть `none`:

| Проверка | Что означает, если не ноль |
|---|---|
| LaTeX leaking outside math | формула не собралась, в тексте остались команды вида `\mathbf` |
| words split by a formula | короткая формула разрезала слово: `at positio$n$n` |
| numbers that lost digits | **самое опасное** — из `0.0001` пропали цифры |
| broken image links | картинка не скачалась, в файле осталась протухающая ссылка |
| prose lines missing | кусок текста потерялся при сборке |

Потерянные цифры — тихая ошибка: текст читается гладко, просто число другое. Поэтому
скрипт сверяет все числа с оригиналом.

Отдельно про строку `unmatched_unique` в блоке формул: это **не** проверка и обычно не
проблема. Она считает формулы, чей текст забрала более длинная формула, которая его
содержит. Тревожно это только если внизу одновременно ругается одна из пяти проверок.

Если проверка не прошла — чини и прогоняй заново:

```bash
python scripts/notion_to_md.py verify --out "<директория>" --markdown <файл> --html <файл>
```

### 5. Напиши саммари

Чтобы саммари были про содержание, а не пересказ заголовков, посмотри темы разделов:

```bash
python scripts/notion_to_md.py digest --out "<директория>"
```

Это дает подзаголовки и первые строки каждого раздела — достаточно для точного саммари,
не затаскивая весь документ в контекст. Не выдумывай термины, которых не видел: сомневаешься,
есть ли в разделе GQA или Mamba — проверь `grep`.

Сложи саммари в JSON (ключ — имя файла без расширения) и примени:

```bash
python scripts/notion_to_md.py summaries --out "<директория>" --summaries summaries.json --title "<заголовок>" --source-url "<URL>" --saved-on "<дата>"
```

```json
{
  "00-intro": "Вводная часть: автор курса и обзорная схема.",
  "01-neural-net-basics": "Фундамент: перцептрон, функции активации, градиенты..."
}
```

### 6. Доложи результат

Сколько формул восстановлено, сколько картинок скачано, результат пяти проверок. Если
что-то не прошло и починить не удалось — скажи прямо, какая проверка и почему, а не
прячь за общим «готово».

## Когда страница устроена иначе

- **Контент выше первого заголовка.** Автор, дата, обзорная схема — скрипт кладет их в
  `00-intro.md`, а не выбрасывает. Если файла нет, значит выше первого H2 был только
  заголовок и оглавление.
- **Нет заголовков H2** — скрипт остановится. Сохраняй одним файлом (`--split single`).
- **Пустой раздел.** Заголовок-разделитель без тела дает файл в пару сотен байт, и
  `digest` по нему молчит. Это нормально, саммари для него можно не писать.
- **Свернутые toggle-блоки.** Их содержимое может не попасть в скрейп. Проверь в rawHtml:
  `notion-toggle` и `aria-expanded="false"`. У последнего бывают ложные срабатывания —
  это еще и кнопки шаринга, так что смотри контекст, прежде чем объявлять потерю.
- **Не Notion, а обычный сайт с KaTeX** (arXiv HTML, блог, лекции) — механика та же,
  скрипт не завязан на Notion. Отличие лишь в том, что картинки обычно не протухают.
- **Формул на странице нет** — можно обойтись без rawHtml, но тогда проверка прозы
  отключится, и скрипт об этом скажет.

Почему сопоставление формул устроено именно так и какие еще грабли встречались —
в `references/pitfalls.md`. Читай, если скрипт повел себя неожиданно или надо его править.
